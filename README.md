# Stereoo Qwen • независимая проверка WebSocket

Это **отдельное тестовое Android APK**, собранное для диагностики проблемы EOF при подключении к `qwen3.8-omni-flash-realtime` на Motorola moto g15.

**Принцип:** в основных тестовых версиях Stereoo Qwen Live используется библиотека **OkHttp**. Здесь намеренно используется независимая библиотека **Java-WebSocket 1.6.0**. Так можно отличить общую проблему транспорта/API от ошибки конкретной реализации OkHttp-клиента.

### Что проверяет
1. WebSocket + ожидание `session.created` без отправки других данных (8 секунд).
2. WebSocket + минимальный `session.update` из официальной документации + ожидание `session.updated` (8 секунд).

Нет микрофона, фото, Android TTS, кнопок BV200 или пользовательской учётной записи Stereoo. Другое applicationId: `ru.stereoo.aiglasses.qwenexternalprobe`, не заменяет прежние приложения.

### Безопасность
- Ключ вводится только на телефоне, хранится лишь в памяти запущенного процесса.
- Нет `Log.d` с токенами и HTTP-заголовками. Журнал не показывает URL/ключ и обрезает информацию сервера.
- Ранее засвеченный ключ следует отозвать и создать новый.
- Alibaba может тарифицировать **даже тестовые подключения**, если модель показывает `No Free Quota`. Прежде чем нажать кнопку, пользователь видит подтверждение.
- **Не загружать ключ** в GitHub, чат или скриншоты. Перед скриншотом скрывать оба поля.

### Как запускать
1. Установить APK, выбрать Singapore Workspace ID, указать API key *из Singapore*.
2. Провести короткий тест 1. Должен прийти `session.created` и через 8 секунд подтверждение устойчивого соединения.
3. Выполнить тест 2, дождаться `session.updated` либо события ошибки/кода закрытия.
4. Прислать скриншот только результатов, полностью закрыв поля ключа и Workspace ID.

Если второй **независимый** клиент тоже получает EOF после session.created, это сильный повод открыть обращение в Alibaba с временем, этапом и кодом закрытия; но нельзя автоматически утверждать, что виноват сервер: общий маршрут сети/прокси тоже может ломать оба клиента.
